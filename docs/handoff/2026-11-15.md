## Goal (changed on Nov 15)
Make the backend work on any claim, not on a few hand-picked demo claims. Method: run a
large claims set on a cheap model, find where the pipeline goes wrong, fix the most common
cause in the backend, rerun.

The product returns more than a verdict: the interpreted claim, component findings, an
explanation whose every statement cites exact source passages, an Almost correction, flags,
limitations and the stage events. The demo must show verdict, explanation and cited sources
together, so source quality is scored, not only the verdict.

short demo; no judging criteria are published. It dates the event Oct 29, 2026, while we

## Spec for the batch tooling (branch feat/batch-eval, off fix/demo-reliability-planning)
1. Batch runner: extend scripts/evaluate_research.py and src/aletheia/evaluation.py. CSV
   input in the format above, no 20-case cap, parallel runs with a limit, a --split
   filter, resume after interruption. Keep the existing guarantees: labels and sources
   never enter prompts, a new output folder per batch, one JSON per claim with result,
   evidence and events, no credentials or raw model responses saved.
2. Source check, run after a batch. For every explanation unit and every part of an Almost
   correction: in code, each cited passage exists in the saved snapshot, comes from the
   cited page and matches its hash; with the judge model, the passage supports the
   statement (supported, partly supported, not supported, one-line reason). Also report
   whether the pipeline's sources include or agree with the labelled source.
3. Report per batch (CSV plus short summary): per claim the end status and stop reason,
   verdict against label, source-check scores, time, model and search calls. Totals by
   case_type. For each miss, the stage at fault: interpretation, planning, search, source
   selection, passage reading, conclusion, or bad citations.
